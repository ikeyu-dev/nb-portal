# 汎用アンケート設計

## 対象

NBポータルにログインした部員が、自由な質問でアンケートを作成・回答・集計する。日程調整と外部公開フォームは対象外。

## 確定事項

- 作成・回答はログインした部員全員が可能。1人につき1回答。受付中は本人が回答を編集できる。
- 質問形式は短文、長文、単一選択、複数選択、日付、数値。質問ごとに必須を設定できる。画像・ファイル添付は扱わない。
- 作成途中のアンケートは入力後約700msで下書きを自動保存する。一覧へ戻る際は保存完了を待つ。回答側も入力中に自動保存し、送信済み回答だけを集計する。
- 締切日時は必須。作成者が変更でき、手動でも即時締切できる。
- アンケート全体の説明は最大4,096文字とする。公開通知のDiscord Embedにも表示するため、入力欄とAPIの両方で制限する。
- 「回答結果を公開する」をオンにすると、受付中からログインした部員全員が回答内容と回答者名を見られる。オフなら作成者のみが見られる。
- 結果を閲覧できる画面では、表示中に15秒ごとに結果を更新する。回答中の入力や編集中の設定は更新で上書きしない。
- 回答が付いた質問は質問文の修正・削除を禁止する。回答済みの選択肢も削除できない。選択肢は追加できる。
- アンケートには最初から「セクション1」を1つ作る。セクションはページとして扱い、タイトル必須・説明任意。下書きでは質問のないセクションを許可するが、公開時には各セクションに質問を1つ以上必要とする。
- セクションは追加・上下移動でき、質問は別セクションへ移動できる。削除時は質問も削除するか、隣のセクションへ移動するかを選ぶ。先頭セクションから質問を残す場合は次のセクションへ移す。回答のある質問は削除できない。
- 回答者はセクションを順番に進み、必須質問を満たしてから次へ進む。回答下書きには最後に開いていたセクションも保存し、再訪時にそこから再開する。回答結果はセクションごとにまとめる。
- 必須回答の検証は「次へ」と最終送信時に行う。「前へ」では未入力でも移動できる。エラー時は該当入力へフォーカスし、入力欄の直下に表示する。
- 公開・編集時の入力エラーも該当項目の直下に表示し、その項目へフォーカスする。公開済みアンケートの未保存変更を破棄するときは確認を行う。
- 回答状況は詳細画面とは別ページに表示する。回答一覧は表計算形式とし、学籍番号・あだ名・氏名・回答日時と質問ごとの回答を列にする。回答別表示では質問と回答を選択し、該当する部員を表で確認できる。
- 作成上限はアンケート全体で質問50件、セクション50件、選択肢は質問ごとに100件。上限到達時は追加操作を無効にして画面に上限を表示する。

## 保存方法

`surveys`にはタイトル・説明・締切・状態・公開設定に加えて、セクション定義を`sections_json`、質問定義を`questions_json`へ保存する。セクションと質問・選択肢には固定IDを付け、質問は`sectionId`で所属セクションを参照する。配列の順番を画面上の並び順として扱う。`survey_responses`はアンケートIDと部員IDの組を主キーにし、回答下書きと送信済み回答を別々のJSON列に保存する。最後に表示していたセクションIDは`current_section_id`に保存する。送信済み回答だけを集計し、編集中の下書きは反映しない。結果表示時は部員名を`members`から解決する。

セクション対応はマイグレーション`0013_survey_sections.sql`で列を追加する。既存アンケートの質問JSONには`sectionId`がないため、Workerの読み込み時に先頭セクションへ割り当てる。既存レコードの回答JSONや質問IDは書き換えない。既存回答の`current_section_id`が未設定・不正の場合は先頭セクションから再開する。

質問定義の更新時には、送信済み回答から実際に使われている質問ID・選択肢IDを調べる。これらの削除と、回答済み質問の文面・形式変更を拒否する。回答の保存・送信時は現在の質問定義と締切を検証する。

## 画面

「その他」とサイドバーからアンケート一覧へ移動できる。一覧には受付中・終了・自分の下書きを表示する。作成画面ではセクションと質問を編集し、質問の追加、必須設定、選択肢編集、公開設定を行う。回答画面は1セクションずつ表示し、「前へ」「次へ」で移動する。回答は入力中に自動保存し、最終セクションで明示的に送信して集計対象にする。作成者は公開・編集・即時締切・結果確認を行える。回答状況へのリンクは詳細画面右上に置く。回答一覧は横スクロール可能な表とし、回答別タブで質問・回答を選ぶと該当者を絞り込む。モバイルでは認証済みレイアウトが確保するDock用下余白を利用する。

## ローカルでの確認

ローカルD1にマイグレーションを適用し、Workerを起動する。Workerには開発専用のAPIキーを渡す。Next.jsを起動するときに`SURVEY_BACKEND_URL`と`SURVEY_BACKEND_API_KEY`を指定すると、アンケートAPIだけをローカルWorkerへ向けられる。その他のAPIの接続先は変わらない。これらの環境変数は開発環境でのみ有効で、本番では通常の`D1_BACKEND_URL`を使用する。

このワークスペースでは、Git管理外の`.env.development.local`にローカル接続先と開発専用キーを設定してある。Workerは`cloudflare/nb-portal-api`で`npx wrangler dev --local --ip 127.0.0.1 --port 8787 --var D1_BACKEND_API_KEY:local-survey-dev-key`、ポータルはリポジトリルートで`npm run dev`を実行する。初回のみWorker側で`npx wrangler d1 migrations apply DB --local`を実行する。
